# 原生 RTT LLM 对战

任务 RTT-LLM-01，2026-10-05。

## 使用

1. 打开 `http://localhost:8080/create/empire-of-the-sun`，登录自己的本地账号。
2. 选择 AI vs AI，日军／盟军分别选择状态机与 `LLM · 模型名`。双方也可都选 LLM。
3. 选择南太平洋、1942缩短战役或1943缩短战役，设置双方合计请求和报告token额度，创建。
4. 点击“AI 下一阶段”。正常处理完该阶段内反应、会战和战后移动后暂停；预算或接口错误立即暂停并显示“阶段未完成”。不自动换机器人。
5. 侧栏“AI 决策轨迹”显示双方当前决策，LLM摘要置顶：选定动作、简短说明、当前计划、备注、用量与资料。只有创建者及现有管理员能看LLM自由文本；其他观察者无此权限。

展示的是模型明确返回的一句决策摘要与简短计划，不是内部隐藏思维链。计划可能错误或失效；规则是否合法仍由游戏引擎裁定。“提示提供的资料”不表示模型采用了某个条款。

## 安装与启动

本机使用原 `rots-runtime-pve`，公共游戏目录 Junction 指向本源码。`tools/install-rtt-llm.js`根据已核对的原生RTT锚点补丁安装，保留其他运行目录修改；首次保存 `.before-rtt-llm` 备份，重复运行不重复修改。不同版本缺少锚点时拒绝该文件写入，需要人工适配。

```powershell
./tools/start-rtt.ps1 -Action Restart -LlmEnvFile C:/path/to/private-models.env
```

配置文件路径只保存在当前用户私有目录的指针文件，供以后 `Start`／`Restart` 复用。密钥不在网页、棋局选项或代码里。模型名单来自已经配置的provider；下拉可选不保证提供商当前额度可用。

## 状态与恢复

- RTT数据库里的真实棋局是唯一状态来源；模型只接收己方白名单观察和引擎候选。
- 每局锁跨模型请求保留；执行前核对数据库回放序号、状态文本、活动阵营、机器人座位和规则对象。
- `game_llm_runtime`保存阵营隔离记忆、预算、哈希账本、pending和prepared响应。记忆随合法动作在同一事务中提交。
- API发送前保存消费请求数。失败、格式修复、用量未知仍计数；唯一候选不请求模型。
- 已返回而未提交的prepared响应可复用；重启时未知在途请求阻断自动重发，需人工核查后恢复或新建对局。
- 刷新、重启、回退不重置实际费用统计。回退只恢复该回放位置之前的阵营记忆；删局归档私有账本并防止复用ID串局。
- 模型配置、规则包、接口源码或规则资料发生改变，已有局拒绝继续，明确提示新建。凭据正常轮换不改变策略指纹。
- 正常阶段推进上限4096动作，每局LLM动作上限20000；重复无进展目前由预算与动作上限停止，尚无独立循环检测。

```powershell
node tools/test-rtt-llm-server.js
```
