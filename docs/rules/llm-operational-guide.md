# LLM 决策操作说明 OP-LLM-01

2026-10-05。以下是规则与现有接口的简述，不是伊拉斯谟策略，也不是新增裁定。

## 规则来源

- 中文 V3.2：`docs/rules/sources/pdf/eots-v3.2-zh-rules-202402.pdf`，HQ/补给/启动 PDF11–15页 §6.0；攻势17–19页 §7.21–7.29；移动20–25页 §8.0；夺占16页 §6.5；战役胜利41–42页 §16.1–16.4。
- 原英文 V3.2（2021）：https://gmtwebsiteassets.s3.us-west-2.amazonaws.com/EOTS_Rules-2021-LR.pdf ，PDF3页 §1.25、13–15页 §7.21–7.24，用于核对牌面数值与攻势流程。其他窗口随请求提供相关中文来源页，不把本说明当完整规则书。

## 容易误解的事实

- 卡号和单位ID是引用键，不是行动力。牌面 `ops` 是OV；军事事件的 `eventLogistic` 是LV；`metadata.oc/ec` 是情报检定阈值，不能当操作枚举、OV或LV。当前有效激活预算用 `activation.limit/remaining`，选牌前用合法 `cardPreviews`，不要只看牌名。
- HQ的CR是指挥距离、CM是效能；可激活的单位还受启动线、补给、国籍/军种、事件限制。几何距离不能证明有启动线。引擎预览返回eligible=false，表示本接口不能提供该预览，不等同于整个事件不能打；带钩子事件的完整效果正文可能缺失。
- 激活、移动、宣布战斗、反应、战斗、夺占、PBM是不同窗口。`activate_units`中的unit切换激活/取消；`move_offensive_units`中的unit选择移动编组。`done`在移动窗表示结束移动，未移动单位留在原地。
- 攻势目标若是夺占敌控格，需要地面占领能力；单独航母/舰船/空军轰击不能取得控制。两栖需检查实际ASP、合法海上护航和敌方ZOI；支援空军/航母可以在合法战斗航程内格外参战，不必全挤入战斗格。编组、落点、航程、堆叠最终以当前引擎候选和查询许可为准。
- OC与军事EC的可宣布战斗格数量不同，不能把EC的多目标方案直接照搬到OC。任何模型的“兵力足够”只是计划判断，未验证的敌方反应能力不能当零；合法也不保证会获胜。
- 前沿基地、HQ、护航和ASP要共同支撑进攻链。可以先集中、补给或前推，再执行下一张牌的攻势；“用满激活量”不是通用目标。反应/PBM遵守各自候选，不能视为任意战略移动。

## 软件事实与目标

`currentDecision`是当前程序事实；`memory`是模型过去的计划或程序历史，旧计划不能覆盖新事实。地图里的engineHex与印刷mapId不同，数字应与当前名称/单位ID共同核对。地图邻接是公开地理，特殊连通、启动/补给路线及合法移动另由引擎查询判定。

南太平洋按第6回合结算VP，盟军使日本VP≤5、日本使VP≥6；政治意志0为日本胜。采用现有引擎投影和SP-17.10.7说明，不把“如果现在计分”当已结束。大战役另按§16.1–16.3的本州投降、封锁、政治意志和终局轰炸条件，不能套用南太平洋VP方向。

每次需要模型调用时，在同一次回答更新三层计划：战役胜利路径、当前回合目标、本次攻势任务。任务写具体地图目标与地面/护航/支援单位ID、下一步和重评条件；模型只提交当前candidateId，计划本身不会自动移动单位。程序追加的recent是已执行事实；计划里的stage、完成声明和胜利预测仍是模型声明。
