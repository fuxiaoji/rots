# 伊拉斯谟 PvE 模型理解

## 图表组成

伊拉斯谟 v2.0 汉化附件共 12 页，结构对称：

| 阵营 | 决策轴 | 共用过程 |
|---|---|---|
| 日本 | 早期、中期、终局 | 卡牌选择、任务部队编成、反应 |
| 盟军 | 早期、中期、终局 | 卡牌选择、任务部队编成、反应 |

日本使用 PDF 第 1-6 页，盟军使用第 7-12 页。

## 不是一个单层有限状态机

伊拉斯谟更适合实现为“阶段状态 + 决策图 + 规则服务”的组合：

- 阶段选择器根据回合、领土和目标状态选择早期/中期/终局图。
- 决策图按 A、B、C 等条件节点行走，并记录 YES/NO 分支。
- 选牌过程对手牌分类、排序，并可能包含掷骰。
- 任务部队编成需要调用引擎的移动、补给、战斗估值和合法性服务。
- 反应过程需要读取当前攻势、情报条件、可用反应牌和可达单位。

因此，AI 决策图不能自己复制一套规则判断；它必须调用引擎的权威查询接口。

```json
{

  "chart_page": 1,
  "chart_phase": "early",
  "nodes": [
    {"node": "A", "value": true, "evidence": ["..."]},
    {"node": "B", "value": false, "evidence": ["..."]}
  ],
  "random_events": [],
  "selected_action_id": "...",
  "fallback": null
}
```

## 实现前置条件

1. 将每页流程图逐节点转写成结构化 YAML/JSON。
2. 给每个条件节点绑定引擎查询和 PDF 页码。
3. 明确图表无法产生合法动作时的回退策略。
4. 建立人工走图黄金样例，再开始 PvE 集成。
