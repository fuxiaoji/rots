# 引擎状态模型初稿

> 这是 P2 的输入清单，不是最终 schema。每个字段仍需绑定具体规则 ID。

## 顶层状态

- `scenario_id`、规则版本、当前回合和当前步骤。
- 当前主动阵营、攻势阵营、反应阵营和优先权持有者。
- 随机种子、已消费随机事件序号和完整事件日志。
- 胜负状态、终止原因与计分状态。

## 卡牌状态

- 双方牌库、手牌、弃牌堆、移出游戏区和未来攻势区。
- 策略牌编号、类型、行动值、情报值、事件约束和一次性效果。
- PASS 可用性、回合抽牌修正与战略作战造成的手牌变化。
- 玩家视图必须隐藏对手手牌和其他私有信息。

## 地图与单位状态

- 格子、相邻关系、地形、港口、机场、资源、国别与控制权。
- 单位阵营、国籍、类型、军力面、位置、补给、启动和是否参加战斗。
- HQ 的位置、效率、指挥范围、国籍限制与转移状态。
- ZOI/AZOI、补给线、战略运输路径与合法移动路径应由基础状态派生，避免存储过期缓存。

## 战略与政治状态

- 日本资源、两栖运输点数（ASP）和补员池。
- 美国政治意志、战争进程、战略海军态势。
- 欧洲战事（WIE）与双方内部军种对立（ISR）。
- 菲律宾、马来亚、荷属东印度、缅甸、印度、中国、澳大利亚和日本等国家/区域状态。

## 临时解析状态

- 当前卡牌及 OC/EC 模式。
- 当前攻势 HQ、启动单位、移动记录和声明的战斗格。
- 每个战斗格的参战单位、情报条件、反应移动和战斗结果。
- 未完成的反应窗口、待分配打击值、撤退、战后移动和强制选择。

临时解析状态必须可序列化，以便在人类或 AI 决策点暂停、保存和恢复。
